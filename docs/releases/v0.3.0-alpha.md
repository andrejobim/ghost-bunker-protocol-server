# Ghost Bunker Protocol Server v0.3.0-alpha

## Summary

Staging-oriented production hardening for the reference server: Docker packaging, reverse-proxy
deployment guide, `prod` profile, configurable WebSocket origins, optional subprotocol enforcement,
graceful shutdown with `SERVER_SHUTDOWN` GOODBYE, identity-free metrics, and a Protobuf load
simulator.

**Server-side only** — the web client is unchanged. Protocol and `.proto` are unchanged.

## Added

- `Dockerfile` and `docker-compose.yml` for containerized staging runs.
- `docs/reverse-proxy-deployment.md` (nginx/Caddy, Privacy-Max proxy logging).
- `src/main/resources/application-prod.yml` (`prod` profile).
- Configurable `ghostbunker.websocket.allowed-origins` and `required-subprotocol`.
- `GracefulShutdownService` — broadcasts `GOODBYE` / `SERVER_SHUTDOWN` on JVM stop.
- Canonical `Goodbye.message` strings via `GoodbyeReasonMessages` on the wire.
- Micrometer metrics (`ghostbunker.*`) with tags limited to `code` / `reason` enums only.
- `GhostBunkerLoadSimulator` — synthetic Protobuf clients for load smoke tests.
- `ProductionHardeningIT` — subprotocol, shutdown, and metrics privacy checks.

## Privacy-Max status

- Tomcat access logs remain disabled; no payload/ciphertext/IP logging in application code.
- Metrics must not use `ip`, `session_id`, `user_id`, `room_id`, or `nickname` labels
  (`ManagementConfig` rejects forbidden tags at registration).
- Actuator HTTP/Tomcat auto-metrics disabled; scrape `:8081/actuator/prometheus` on internal network only.

## Known limitations

- **Staging, not full production** — single-node, in-memory, no clustering.
- **No independent cryptographic audit.**
- Empty `allowed-origins` in `prod` rejects all handshakes until configured.
- Load simulator is a smoke tool, not a published benchmark suite.
