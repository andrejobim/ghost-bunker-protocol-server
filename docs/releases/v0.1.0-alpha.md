# Ghost Bunker Protocol Server v0.1.0-alpha

## Summary

This is the first **public alpha** of the Ghost Bunker Protocol reference server: a
single-node WebSocket relay that routes **opaque client-encrypted ciphertext** between
participants of the same room, without server-side identity, persistence, or message
history.

## Features

- Reference server implementation (Java 21 + Spring Boot).
- WebSocket endpoint that speaks Ghost Bunker Protocol v0.1.
- Protobuf envelope contract for binary WebSocket frames.
- In-memory sessions and rooms (state is lost on restart).
- E2EE ciphertext routing (the server does not decrypt or inspect payloads).
- Canonical public error messages (`ErrorMessage.message`) driven by `ErrorCode`.
- Manual test clients and a documented manual testing workflow.
- Automated unit + integration tests (`mvn clean verify`).

## Privacy-Max status

- Privacy-Max is a **best-effort operational profile**, not a guarantee.
- The project includes a Privacy-Max profile document and an accompanying privacy audit
  write-up, focused on preventing application-level logs from leaking identifiers or
  payloads.

## Known limitations

- **Not production-ready.**
- **No independent cryptographic audit** has been performed.
- Single-node only (no clustering, no shared state, no cross-instance routing).
- No persistence (no database, no message history, no offline delivery).
- No accounts, no long-lived identity, no authentication.
- WebSocket runs over TCP; network-layer metadata (e.g. client IP) is out of scope for
  application-layer privacy controls.

## Not production-ready warning

This release is **experimental / work in progress**. Do not deploy it as a production
service, and do not rely on it for sensitive communications.
